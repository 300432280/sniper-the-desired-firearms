
**Layer verdict**: Cloudflare is the upstream CDN (passive — `Server: cloudflare`, `CF-RAY` always present). The 403 BODY is generated by Wordfence at origin and passed through CF. Operationally-blocking layer is Wordfence.

**Runtime-consumer re-grep** (per persona note):

Single read site. Worker (`worker.ts`) and scheduler (`crawl-scheduler.ts`) only consume `hasWaf` boolean. `wafType` is cosmetic-for-runtime, but informative for operators triaging issues (Wordfence has plugin quirks Cloudflare doesn't — e.g. learning-mode 410, IP-locked admin pages).

**Proposed value**: `wordfence`. Optionally record CF passively in `wafProbeEvidence.cfHeaders` (R1 already does).

## Field 2: perPage — 48 (R1) vs 12 (DB)

**Verdict: both-wrong-for-runtime; correct value is 100.**

Runtime channel for woocommerce adapter (re-read):
```
// backend/src/services/scraper/adapters/woocommerce.ts:293
const perPage = Math.min(options?.perPage ?? 100, 100);
```
The adapter's primary catalog channel is WC Store API at `/wp-json/wc/store/v1/products`, which honors `per_page` up to 100 by WP REST default.

Live test:
```
$ curl -A "<browser-ua>" "https://dantesports.com/en/wp-json/wc/store/v1/products?per_page=100&page=1"
[100-item JSON array; first slug=beretta-1301-tactical-mod-2-m-lok-vietnam-tiger-stripe]

$ curl -I /en/wp-json/wc/store/v1/products?per_page=100
x-wp-total: 2130
x-wp-totalpages: 22       # 2130/100 = 21.3 -> 22 pages, math checks
```

HTML category page silently caps:
```
$ curl /en/product-category/firearms/?per_page=100  -> 12 unique product links
$ curl /en/product-category/firearms/?per_page=48   -> 49 unique product links (48 + duplicate header link)
$ curl /en/product-category/firearms/?per_page=12   -> 12 (default)
```
The theme's `<select>` only honors 12/24/48; any value above 48 reverts to 12.

**Proposed value**: `perPage: 100` (matches Store API runtime). If `paginationPattern` needs an HTML-fallback value, expose it as `paginationPattern.htmlPerPage: 48`.

## Required Verdicts

### Wordfence-vs-cloudflare-passive layer verdict
Both layers present. Cloudflare is **passive CDN** in front (Server: cloudflare, CF-RAY on all traffic). Wordfence is **active plugin** at origin (issues 403s with `Generated by Wordfence` body marker on XSS-shaped queries and bot UAs). Operationally-blocking layer = Wordfence. **`wafType` should be `wordfence`.** Record CF passively in `wafProbeEvidence.cfHeaders`.

### WPML canonical-language verdict
Default = FR (apex 302 -> /fr/). English crawl path = `/en/`. WC Store API + WP REST under `/en/wp-json/...`. EN `x-wp-total` = 2130. FR `x-wp-total` = 2131 (one FR-only product). All catalog/API endpoints in `siteProfile` must use `/en/` prefix.

### wafType runtime-consumer re-grep verdict
`grep -rn wafType backend/src/` returns ONLY `profile-validator.ts:122-125` (non-null check when `hasWaf=true`). Worker, scheduler, watermark-crawler, catalog-crawler all read `hasWaf` boolean column — never `wafType` string. Persona note is verified: `wafType` is cosmetic for runtime but valuable for operator triage.
