### Most-surprising divergences (top 3)

1. **`wafType: 'wordfence'` vs `'cloudflare-passive'` (row 4).** DB classified the upstream CDN; candidate classified the actively-blocking origin plugin. DB's own `wafProbeResult` explicitly logs "XSS probe 403" yet tags `cloudflare-passive` - that's the harness gap. Wordfence is unambiguous in the 403 body (`Generated by Wordfence`).
2. **`perPage: 48` vs `12` (row 13).** DB shipped the page-1 default. SKILL.md Stage 5 requires probing the max-verified limit; `?per_page=48` was confirmed honored. 4x reduction in HTML fetches for any HTML-fallback crawl.
3. **`crawlers.maintain.verifyMethod` absent in DB (rows 26-27).** SKILL.md Stage 3 prescribes deterministic value for WC (`store-api` + `/wp-json/wc/store/v1/products`); the worker silently skips verification when the field is missing. DB has no value -> maintain phase effectively disabled.

### SKILL.md harness gaps (1-3)

1. **No defined slot for multilingual sites.** dantesports.com is WPML-managed (FR default, `/en/` for English). DB captured a structured `multilingual: {plugin, crawlLanguage, defaultLanguage, apiPrefix}` block. SKILL.md never mentions multilingual platforms. The harness should detect `<link rel="alternate" hreflang>` or WPML/Polylang markers and emit a structured `multilingual` block. Currently downstream code has to re-derive the language path from `catalogUrls` strings.
2. **WAF tag ambiguity when CDN + origin plugin both present.** SKILL.md has separate entries for `cloudflare-passive` and `wordfence`/`malcare`, but no rule for how to label a site with BOTH (CF in front + Wordfence at origin). Stage 2 says "set hasWaf true only when WAF actively blocks" - decides the boolean but not the label. Add explicit rule: when both layers exist, label by the operationally-blocking layer (`wordfence`), not the upstream CDN; record CDN passively in `wafProbeEvidence`.
3. **No prescribed slot for category walk-stats (page totals).** DB had `categoryStats: {<slug>: {count, pages}}` from a prior walk. Useful runtime info (estimate crawl budget, detect cap drift). SKILL.md's `topLevelCategories.categories[]` only stores `count` - no `pages` field. Add `pages?` or `walkedAt?` to make page-total persistence first-class.

### Calibration gaps in this Round 1

- `catalogUrls` not exhaustively walk-and-deduped per Rule C - relied on slug-name inference to drop 5 marketing-aggregate categories (DB kept them as inclusion-safe). Walking each excluded category to prove redundancy was skipped due to rate budget.
- BATCH 3 (rapid burst) saw all 10 requests succeed; DB observed 410 rate-limit at burst #8. Worth re-probing from production crawler IP.
