## B. Cross-cutting lessons learned by artifact

### B1. SKILL.md gaps (new + reinforced, biggest first)

1. **`productCountMethod.url` MUST be path-only, not absolute.** R3-frontierfirearms catch: `product-count-probe.ts:233` prepends `${origin}` → absolute URL produces double-prefix → fetch fails → silent null. SKILL.md must specify "path-only, leading slash required" in the productCountMethod shape table.
2. **Probing siteProfile.domain on apex vs www is mandatory.** R3-gagnonsports BLOCKING catch: apex (`gagnonsports.com`) returns openresty 403/404; canonical is `www.gagnonsports.com` (Cloudflare 200). Both R1 + R2 ran against apex. Skill must check `<link rel="canonical">` AND test reachability on BOTH apex and www before declaring a candidate; mismatch → use the working host.
3. **`searchUrl` MUST be probed with a junk-keyword control body diff.** R3-durhamoutdoors trap: `?s=glock` and `?s=xyz789nonsense` returned IDENTICAL 68366-byte bodies → query silently ignored. "200 = valid" heuristic fails. Skill rule: candidate searchUrl must produce a DIFFERENT body for keyword vs nonsense; otherwise mark `null`.
4. **`/sale/` and similar "promo container" URLs can hide many UNIQUE products.** R3-gagnonsports finding: `/sale/.../new-used-guns/` had 25/31 products NOT in /firearms/used-rifles or /firearms/used-shotguns. Don't drop promo URLs assuming they're cross-listings; live-dedup before exclusion.
5. **LightSpeed (Lightspeed eCom) uses path-segment pagination `pageN.html`, NOT `?page=N`.** R3-gagnonsports finding: live `/collection/` has only `<link rel="next">` — no rel=last, no page-list, no "X of Y" text. `html-pagination` method shape-valid but functionally broken. SKILL.md must add LightSpeed to platform-specific pagination table.
6. **Shift4Shop/3dcart platform** (`vcart=26.19.0`, `_3d_cart` JS var, `.asp` URLs, pagination suffix-replace `-{N}.html`) not in SKILL.md primary platform table. Add fingerprint + pagination shape.
7. **`crawlers.maintain` block MUST exist** even when verifyMethod is the only field. `worker.ts:769-772` early-returns when block is missing — verify worker silent no-op. SKILL.md must list this block in required output fields.
8. **WAF migration detection**: DB-recorded WAF type can be 40+ days stale (thegundealer: sgcaptcha → Cloudflare-passive). Skill must always heavy-probe fresh; never trust DB wafType without re-validation.
9. **Sample broadening 3× (B9 sustained-pattern + multi-UA matrix) caught WAF misclassifications** at durhamoutdoors (R1 said active, R2 confirmed passive across 4 UAs × 30 pages) and thegundealer (5-UA × 86 pages with no sg-captcha residue).
10. **`hasWaf:true` defensive flag with `cloudflare-passive` wafType is the DOMINANT bug pattern** — confirmed on 6+ batch-5 sites (aagcanada, durhamoutdoors, frontierfirearms, jobrookoutdoors, rdsc, store.prophetriver, irunguns Sucuri-passive). Runtime cost: perPage 50→20 throttle + Playwright forced + WAF cookie path. Same as batch-4 lesson — still happening because no automated linter detects it. Skill must FAIL stage 2 if `hasWaf:true` AND `wafType` ends in `-passive`.
11. **Audit IP vs production IP/UA divergence**: R1 on g4cgunstore (batch-4) and aagcanada (batch-5) overcalled WAF severity because audit IP saw rate-limit responses that production rotating-UA pool doesn't trigger. Skill must instruct: use production UA pool fingerprint, not single curl UA.
12. **`searchUrl` deterministic probe (B4)** missed by R1 on 4 batch-5 sites (frontierfirearms, durhamoutdoors, aagcanada). Skill Stage 3 must enforce this as a non-skippable check.

### B2. Runtime code gaps (new finds)

1. **`product-count-probe.ts:233` `${origin}${m.url}` requires `m.url` to be path-only** (leading slash). Currently no validation that rejects absolute URLs. Fix: at validateMethod (`L129-137`) or new check, reject `m.url` if `m.url.startsWith('http')`. Add unit test.
2. **`productCountMethod.method = "wc-store-api-header"` is NOT in VALID_METHOD_NAMES** but operators clearly believe it should be (DB on thegundealer + appears in audit history). The label looks canonical — easy mistake. Either add it as an alias or reject explicitly with a "did you mean `wp-rest-header`?" hint.
3. **B8 pair-rule (productCountMethod endpoint matches verifyMethod surface) is SKILL.md convention only.** `profile-validator.ts:155` does NOT code-enforce. Operator can promote an invalid pairing. Add a validator check or document explicitly that B8 is advisory.
4. **`adapter-registry-mismatch.ts` `platform != adapterType` warning** confirmed working on g4cgunstore (batch-4) but the `warnedDomains` set is shared across both branches — a domain with both drifts only logs once. Acceptable today; flag for future split.
5. **R3 standing task pays off**: re-tracing `worker.ts:381-781` confirmed batch-3 `worker.ts:544` push-placement fix is real and effective in production for greatnorthgunco (batch-4) and confirmed `verifyMethod` runtime-equivalence for json-ld/detail-page on multiple batch-5 sites.

### B3. Harness/methodology gaps

1. **Apex vs www blindness** — both R1 AND R2 ran against the wrong host on gagnonsports. R3's broadening test (different UAs) accidentally surfaced www host returning 200 while apex returned 403. Harness must explicitly probe both apex/www in Stage 1 (canonical-host detection) — not just one.
2. **R2 timeout / session-limit recovery worked**: 5 R2 agents hit session limits (4 with no artifacts written, 1 with artifacts intact). Re-spawning the 4 missing R2s in a fresh session completed cleanly. Lesson: persistent on-disk artifacts (not chat history) are the recovery surface.
3. **Adversarial broadening 3× (R3 SKILL.md directive) found 4 substantive counters this batch.** Validated the calibration-mode rules added to SKILL.md after batch-4. R3 round continues to deliver value even when R2 looks clean.
4. **"Untested-by-harness" classification working** (aagcanada R3 self-marked searchUrl as untested at runtime since adapter parse not executable from agent's seat). The SKILL.md calibration rule is being followed.
5. **Junk-keyword diff test** (R3-durhamoutdoors method) is a generic adversarial pattern that should be added to skill: when a probe claims success on a value, run the same probe with a known-invalid value; if the response is identical, the original was a false positive.
6. **Cross-batch verification standing task**: R3 agents traced batch-3/batch-4 merged fixes against batch-5 live sites. Confirms the worker.ts:544 push-placement fix continues to work. R3 directive 3 is paying its weight.
